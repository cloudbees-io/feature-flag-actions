= Patch Feature Flag Config

`PATCH` the configuration of a Feature Flag.

NOTE: This is a low-level action intended to be called by other actions in this repo. For typical use cases prefer link:../../enable-flag[enable-flag] or link:../../disable-flag[disable-flag].

== Inputs

[cols="2a,2a,2a,5a",options="header"]
.Input details
|===

| Input name
| Data type
| Required?
| Description

| `api_token`
| String
| No
| The Unify API token. If not defined, the action will use a secret named `FEATURE_FLAG_ACTIONS_API_TOKEN` or will error.

| `app_id`
| String
| Yes
| The Unify application ID with which the Feature Flag is associated.

| `flag_id`
| String
| Yes
| The Feature Flag UUID.

| `env_id`
| String
| Yes
| The Unify environment ID in which the Feature Flag is to be PATCHed.

| `payload`
| String
| Yes
| The JSON payload to PATCH the flag config with e.g. `{"enabled":true}`. See schema below.

|===

=== `payload` schema

[source]
----
{
  "enabled": boolean,
  "defaultValue": any,
  "conditions": [
    array<object>
  ],
  "stickinessProperty": string,
  "variantsEnabled": boolean
}
----

Describing this payload in more detail is beyond scope for now. Easiest way to grok e.g. the `conditions` element is to mimic the desired flag rule config in the link:https://cloudbees.io/[Unify dashboard] and inspect the `PATCH` request payload.

== Patching flag conditions

When the `payload` contains a `conditions` list this action applies special merge logic rather than replacing the existing conditions wholesale.

=== Empty conditions list

Passing an empty `conditions` list (`[]`) is explicitly rejected with an error. Sending an empty list to the API would silently delete all existing conditions on the flag, which is almost never the intent.

=== Non-empty conditions list

When new conditions are supplied the action:

1. GETs the current flag configuration from the API.
2. Prepends the incoming conditions to the existing conditions list, giving the new conditions precedence in evaluation order.
3. Deduplicates — any incoming condition that is an exact JSON match of an existing condition is not added twice.
4. Issues the PATCH with the merged conditions list.

NOTE: This intentionally does not support modifying the evaluated flag value of existing conditions. If an existing condition overlaps with a new one, both will be present in the list — the new condition takes precedence by virtue of being first. Any obsolete conditions left behind after a merge will need to be manually cleaned up via the link:https://cloudbees.io/[Unify dashboard].
